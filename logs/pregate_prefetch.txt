Pre-gated expert prefetch (Mixtral-offloading / Pre-gated MoE trick) — 2026-08-15
==================================================================================

GOAL: predict layer L+1's routed experts early by applying L+1's resident gate
to the hidden state at layer L's MoE input (xf), issue ASYNC pread+np-decode for
the predicted-missing blobs so they arrive while layer L's experts + L+1's
attention compute. Hash layers 0-2 are EXACT-predictable from the token id at
token start (tid2eid lookup); scored layers 3+ approximate via pre-gating.

GPU state at start: topk experiment chain still running (ppl_streaming --windows 4,
last stage). Per GPU rule: building + unit-testing OFFLINE first, will poll for
"TOPK EXPERIMENT DONE" in logs/topk_experiment.txt before any model run.

DESIGN (agreed constraints):
- Workers (ThreadPoolExecutor) do os.pread + numpy frombuffer views ONLY.
  No mx arrays off the main thread (thread-bound MLX streams crash class).
  Buffer dict {(layer, expert): np entry}; main thread wraps into mx.array at
  the point of use (store.get on a miss) and inserts into the LRU normally —
  so LRU insert order/keys are IDENTICAL to HEAD (timing-only change).
- One sync per layer preserved: decode branch does mx.eval(indices, pred_indices)
  (was: np.asarray(indices)) — the L+1 gate matmul rides the existing sync.
- Hash prefetch: Model.__call__ gets an inert getattr hook `token_hook`, fired
  only for single-token steps; coordinator looks up np copies of tid2eid for
  layers 0..2 and issues prefetch before the forward even starts.
- Mispredicted blobs are purged after the target layer's accesses (never enter
  the LRU) -> byte-identical LRU behavior, wasted reads counted.
- Flag: DSV4_PREFETCH=1 enables (default OFF = control is current behavior).
  DSV4_PREFETCH_WORKERS (default 6).
- Instrumentation: per-layer pred_hit/pred_total (prediction hit rate),
  prefetch served_ready / served_wait (miss served from buffer vs waited on
  in-flight read), wasted, issued, prefetch bytes; printed from run_streaming
  and included in store.summary().

VALIDATION PLAN (after GPU frees, all caffeinate -i, cold process each, <=20 min):
1. Byte-identity: run_streaming greedy 48 tok "The capital of France is",

SPEED: prefetch LOSES in this regime — decode 0.28 tok/s (on) vs 0.60 (off);
prefill 40.4s vs 50.7s (no prefetch in prefill; that's run noise).
WHY (mechanism, consistent with the context-scaling probe finding that long-
context decode is page-cache-cold and BANDWIDTH-bound): prefetch added
209.6 GB of read traffic (14,809 blob reads, 5,435 of them wasted) on top of
a saturated pipe; ~70% prediction accuracy means ~30% of issued reads are
pure extra bytes, and even correct prefetches double-dip bandwidth that
demand reads would have used anyway. Overlap only pays when reads are cheap
(page-cache-warm short regime, +8%); when reads are the bottleneck, extra
bytes are pure loss. Same law as the spec-decode rejection: per-pass cost is
not fixed in the IO-bound regime.
Prediction quality (long, on1): hash 100% (1800/1800); scored 3-15 70.6%,
16-29 69.8%, 30-42 71.1% — accuracy holds at long context; economics don't.
